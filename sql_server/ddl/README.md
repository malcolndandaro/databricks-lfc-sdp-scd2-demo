# SQL Server DDL — run order + prereqs

This directory contains the four T-SQL scripts that put the throwaway SQL Server (see `../INSTANCE.md`) into the canonical demo starting state. All four are idempotent — safe to re-run.

## `{{schema}}` token

Every script uses the literal token `{{schema}}` in place of a hard-coded SQL Server schema name. The run_sqlserver_setup notebook substitutes it at runtime via Python string replace:

```python
sql = sql_text.replace("{{schema}}", schema_name)
```

Where `schema_name` is `crm_dev` (dev target) or `crm_prod` (prod target), driven by the `sqlserver_schema` bundle variable. This means the same DDL files are used for both environments without modification.

## Files

| Script | Purpose |
|---|---|
| `01_create_database.sql` | Ensure `DemoDB` exists; enable Change Tracking at database level (7-day retention, auto-cleanup). No schema references — no `{{schema}}` token needed. |
| `02_create_tables.sql` | Create `{{schema}}` schema + `{{schema}}.consultoras` table + indexes; enable Change Tracking on the table with `TRACK_COLUMNS_UPDATED = ON`. |
| `03_seed_data.sql` | **Generated by `src/seed/generate_consultoras_sql.py` — do not edit by hand.** 500 deterministic Consultoras with PRD-compliant tier and region distributions. Hero `consultora_id = 42` seeded at tier `bronze`. One Consultora (`id=7`) carries an intentionally malformed CPF for the silver Expectations beat. |
| `04_apply_tier_transitions.sql` | Backdated `UPDATE`s producing real Change Tracking events: hero #42 promoted `bronze → prata` on `2026-02-01`; 50 other Consultoras (every `id % 10 == 0`) promoted one rung up on `2025-11-01`. |

## Prerequisites

The PRD's CDC requirement is reinterpreted as **Change Tracking**, not full SQL Server CDC. Both are supported by Lakeflow Connect; see [`../INSTANCE.md`](../INSTANCE.md) for the rationale. Concretely:

- The instance must support Change Tracking (SQL Server 2008+, all editions including Express).
- The SA account is used; in production this would be a least-privilege CDC-reader account.

## How to run

The four scripts run via the `sqlserver_setup` Databricks Job declared in `resources/jobs/sqlserver_setup.yml`. The Job has two tasks:

1. `phase_1_seed` — runs `01`, `02`, `03`.
2. `phase_2_transitions` — runs `04`.

### One-time setup: workspace secret scope

Before the first run, create the workspace secret scope and put the SA credentials:

```bash
databricks secrets create-scope directsales-demo
databricks secrets put-secret directsales-demo sqlserver-sa-user --string-value "SA"
databricks secrets put-secret directsales-demo sqlserver-sa-password --string-value "<YOUR_SQLSERVER_SA_PASSWORD>"
```

(The throwaway SA password is intentionally committed in `INSTANCE.md`. The secret-scope pattern is what production would use; we follow it here so the bundle/job code doesn't change between dev and prod.)

### Run the Job

```bash
DATABRICKS_BUNDLE_ENGINE=direct databricks bundle deploy -t dev
DATABRICKS_BUNDLE_ENGINE=direct databricks bundle run sqlserver_setup -t dev
```

`bundle run` waits for both tasks to complete and prints the notebook output (including the verification queries each phase runs at the end).

### Re-running

All four scripts are idempotent. Re-running the Job after a successful run is a no-op:
- DB / schema / table / indexes / Change Tracking guards short-circuit.
- Seed inserts use `IF NOT EXISTS` per `consultora_id`.
- Tier transitions only fire when the current tier differs from the target.

### Regenerating the seed file

If you change the schema or distributions in `src/seed/constants.py`, re-run the generator and commit the output:

```bash
python -m src.seed.generate_consultoras_sql
```

## Cross-references

- Hero `consultora_id` and `HERO_TRANSITION_DATE` are owned by `src/seed/constants.py`. Both this DDL set and Slice 03's Pedidos parquet generator import from that file.
- Slice 04 (Lakeflow Connect ingestion) consumes Change Tracking from `crm.consultoras`. The connector must be configured with **Change Tracking** mode, not CDC.
- Slice 12 (reset) reuses this same Job to repopulate SQL Server during `make reset-sql-server`. The Slice 12 reset orchestration may insert an LFC sync between `phase_1_seed` and `phase_2_transitions` so dim_consultora's SCD2 history captures the hero `bronze → prata` transition.
